# HFD

HFD — серверная часть системы для ведения данных о пациентах и медицинском персонале, организации опросов и получения сводной статистики. Сервис предоставляет REST API на ASP.NET Core и хранит данные в PostgreSQL.

### Возможности

- управление пациентами и связанными с ними контактами сотрудников;
- управление медицинскими работниками и участками;
- создание, просмотр, изменение и удаление опросов, проверка необходимости прохождения и получение последнего опроса пациента;
- получение сводных данных по опросам за месяц или период и по индикатору;
- вход по номеру телефона и паролю, а также вход через Telegram-провайдера;
- фоновые задачи для работы с опросами и напоминаниями.

Доступ к API защищён авторизацией и ролевыми ограничениями: например, управление пациентами доступно администраторам и медсёстрам, а участками и медицинским персоналом — администраторам. Документация API публикуется через Swagger.

### Структура решения

- `Hfd.Backend` — ASP.NET Core API, контроллеры и настройка приложения;
- `Hfd.BizLayer` — прикладные сценарии и фоновые задачи;
- `Hfd.DbLayer` — модели хранения, сервисы доступа к данным и миграции Entity Framework Core;
- `Hfd.Models` — модели данных API;
- `Hfd.Contract` — контракты и преобразования между моделями;
- `libs/common`, `libs/identity`, `libs/provider` — общая инфраструктура, аутентификация и интеграция с провайдером (подключаются как Git submodules).

## Требования

- .NET SDK 8.0
- PostgreSQL
- Git с поддержкой submodules

## Получение и запуск

Клонируйте репозиторий вместе с подмодулями:

```bash
git clone --recurse-submodules <URL-репозитория>
cd hfd
```

Если репозиторий уже клонирован без подмодулей, выполните `git submodule update --init --recursive`.

Создайте в PostgreSQL базы `hfd` и `hfd.users` либо укажите существующие базы в настройках. Скопируйте `Hfd.Backend/appsettings.json` в локальную конфигурацию и проверьте параметры подключения, затем запустите API из корня репозитория:

```bash
dotnet restore hfd.sln
dotnet run --project Hfd.Backend/Hfd.Backend.csproj
```

При старте приложение применяет миграции базы HFD и заполняет начальные данные Identity. Swagger доступен по адресу, указанному в выводе приложения (в стандартном локальном профиле — `https://localhost:5001/swagger`).

## Конфигурация

Основной файл настроек — `Hfd.Backend/appsettings.json`. Для локальной разработки можно использовать такие значения:

| Параметр | Назначение | Пример |
| --- | --- | --- |
| `providerOptions:tgUri` | HTTPS-адрес gRPC-провайдера | `https://localhost:6001` |
| `providerOptions:hostUri` | Адрес приложения | `https://localhost:5001` |
| `ConnectionStrings:HfdConnection` | Подключение к базе HFD | `Host=localhost;Database=hfd;Username=postgres;Password=postgres` |
| `ConnectionStrings:IdentityConnection` | Подключение к базе Identity | `Host=localhost;Database=hfd.users;Username=postgres;Password=postgres` |

Значения пользователя и пароля выше предназначены только для локальной разработки. Не используйте их в production и не храните реальные пароли в репозитории. Переопределяйте настройки через переменные окружения .NET, например `ConnectionStrings__HfdConnection` и `ConnectionStrings__IdentityConnection`.

В конфигурации также задаются уровни логирования Serilog и путь к файлам логов. В предоставленном примере это `%ALLUSERSPROFILE%\\HFD\\Logs\\Main\\Hfd.log` с ротацией по дням.

## Docker

В корне проекта находится `Dockerfile`, который собирает и публикует API в образе .NET 8. Собрать образ:

```bash
docker build -t hfd:latest .
```

Для запуска контейнеру нужны доступ к PostgreSQL и корректные настройки приложения (включая строки подключения). Пример CI/CD для сборки и развёртывания приведён в `.gitlab-ci.yml`.
